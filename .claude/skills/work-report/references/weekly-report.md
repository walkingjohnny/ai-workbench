# 周报撰写指南

## 格式模板

```
# 周报 — [姓名] [YYYY-MM-DD ~ YYYY-MM-DD]

## 本周成果
- [成果 1]：[具体产出 / 量化指标]
- [成果 2]：[具体产出 / 量化指标]
- [成果 3]：[具体产出 / 量化指标]

## 关键进展
| 事项 | 状态 | 说明 |
|------|------|------|
| [事项 A] | 已完成 / 进行中 / 延期 | [一句话说明] |
| [事项 B] | ... | ... |

## 下周计划
- [计划 1] — 预期产出
- [计划 2] — 预期产出

## 问题与风险
- [问题描述] — [影响] — [需要的支持]
（如无则写"无"）

## 本周反思（可选）
[一两句话，本周学到了什么 / 下周可以改进什么]
```

## 写作要求

1. "本周成果"聚焦**已交付的产出物**，不是过程描述
2. "关键进展"用表格呈现多个并行事项的状态全景
3. "下周计划"带预期产出，不是模糊的方向
4. 量化优先：完成了几个功能、修复了几个 bug、写了多少文档
5. 总长度控制在 3 分钟内可读完

## 信息收集流程

1. 检查当前项目的 `git log --since="1 week ago" --oneline --stat` 获取本周 commit 概览
2. 检查是否有本周的 task 记录
3. 询问用户：
   - 本周除了代码之外的工作（会议、评审、调研、协作等）
   - 下周的重点计划
   - 有没有需要上级关注的风险或问题
4. 基于收集到的信息，按模板组织输出

## 质量标准

- 读者 3 分钟内能全面了解你本周的工作和下周的方向
- 成果可验证，计划可追踪
- 不含套话，不堆砌流水账
- 如果某个事项延期或有风险，在"问题与风险"中诚实说明，不隐瞒
