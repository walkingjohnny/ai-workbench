# 日报撰写指南

## 格式模板

```
# 日报 — [姓名] [YYYY-MM-DD]

## 今日完成
- [具体事项 1]
- [具体事项 2]

## 进行中
- [事项] — 当前进度 / 预计完成时间

## 明日计划
- [计划事项 1]
- [计划事项 2]

## 问题与阻碍
- [问题描述] — [影响范围 / 需要的支持]
（如无则写"无"）

## 备注
（可选，补充说明）
```

## 写作要求

1. 每条事项一句话，动词开头（完成了、修复了、对接了、推进了）
2. 量化优先：用数字、百分比、具体产出物代替模糊描述
3. "进行中"标注当前进度节点，让读者知道卡在哪
4. "问题与阻碍"只写真正阻碍进展的事项，不是吐槽
5. 总长度控制在 1 分钟内可读完

## 信息收集流程

1. 检查当前项目的 `git log --since="yesterday" --oneline` 获取 commit 记录
2. 询问用户：今天除了代码提交之外，还做了什么？（会议、沟通、文档等）
3. 询问用户：有没有卡住的地方？
4. 基于收集到的信息，按模板组织输出

## 质量标准

- 读者 30 秒内能了解你今天做了什么
- 每条事项可追溯（对应 commit、文档、会议）
- 不含套话（"积极推进"、"持续优化"等空洞表述）
